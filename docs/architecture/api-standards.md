# API standards

Status: **planned**. `contracts/openapi/` is empty; no endpoint exists. Workflow:
`/create-api`; skill: `rest-api-design`.

## Contract first

- Each service's HTTP API is described by one OpenAPI 3.1 document:
  `contracts/openapi/<service>.v<major>.yaml`.
- The spec changes in the same commit as the implementation; consumers generate clients
  from it (frontends with `openapi-typescript`).
- Pact consumer tests describe what each consumer actually uses; providers verify them.

## Resource design

| Concern | Standard |
|---|---|
| Paths | `/v1/<plural-resource>/{id}`; sub-resources for ownership (`/v1/orders/{id}/lines`) |
| Actions that change state | sub-resource nouns (`POST /v1/orders/{id}/cancellation`) |
| Identifiers | UUID strings generated by the server (or client-supplied where idempotency needs it) |
| JSON | camelCase fields; ISO-8601 UTC timestamps; money as `{ amountMinor, currency }` |
| Lists | cursor pagination `?limit=&cursor=` → `{ items, nextCursor }`; maximum `limit` enforced |
| Filtering/sorting | explicit query parameters from an allow-list |
| Long-running operations | `202 Accepted` + `Location` of a status resource (order creation) |

## Status codes

| Code | Use |
|---|---|
| 200 / 201 (+`Location`) / 202 / 204 | success variants |
| 400 | malformed request |
| 401 | missing/invalid token |
| 403 | authenticated but not allowed (function level) |
| 404 | not found — also for objects the caller may not see (no enumeration) |
| 409 | state conflict (e.g. cancelling a shipped order) |
| 412 | `If-Match` mismatch |
| 422 | business rule violation |
| 429 | rate limited |
| 503 | dependency unavailable; `Retry-After` when known |

## Errors

`application/problem+json` (RFC 9457): `type` (stable URI per problem), `title`, `status`,
`detail`, `instance` (includes the trace id), and `errors[]` for field validation. No stack
traces, SQL or internal class names.

## Reliability

| Mechanism | Where |
|---|---|
| `Idempotency-Key` header (required) | non-idempotent POSTs that create resources (orders, payments, adjustments) |
| `ETag` + `If-Match` (required on updates) | admin edits of prices, products, stock |
| Timeouts on every outbound call | callers; values set from measurements |
| `traceparent` propagation | all requests (gateway, BFF, services) |

## Documentation and review

- Every operation has `operationId`, summary, security requirement and documented error
  responses.
- Specs are linted in CI (Redocly CLI, planned).
- Breaking changes follow [api-versioning.md](api-versioning.md).

## Trade-offs

REST + OpenAPI was chosen over GraphQL or gRPC for browser clients: simple caching,
generated clients and contract tests with Pact. Composition for admin pages happens in the
admin BFF (ADR-0010), not in services.
